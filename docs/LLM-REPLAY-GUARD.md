# LLM-REPLAY-GUARD：上游流重放容错插件

状态：现行（独立插件，harness llmKit 默认装配；gapMs ≤0 可整体关闭）
归属：挂 `@x-harness/llm` 的 root 层 `llm/stream` waterfall（「回放/路由类拦截」既定中间件位）。

## 1. 问题与方案

上游（服务端/SSE 网关）断流后把已生成文本**从头重发**（实证：回复正文出现「前缀片段+全文」
或「整文精确自重复」拼接，且服务端 usage 按双倍计费——重放发生在上游，本仓消费端只能容错）。
重放通常伴随可观测的帧间停顿。

三态机（`guard.ts`，纯函数面，只作用于 text-delta；thinking/usage/toolcall 直通——
usage 双计费是服务端事实，照落不纠）：

| 态 | 行为 |
| --- | --- |
| PASS | 逐帧直通零延迟（守卫侧维持已放行文本全文追踪供头部比对——内存 O(全文)，与下游累积同量级）；相邻 text-delta 间隔 > gapMs 且已放行 ≥ minEmitted 时进入 HOLD |
| HOLD | 扣留新序列与已放行文本**头部逐位比对**，同时向下游放零宽保活帧（见下）：发散 → 补放行全部扣留（合法续写，零丢失）；比对覆盖到已放行末尾 → 重放前段吞掉、超出部分作为新增尾段放行（下游/UI = 干净单份），转 PASS |
| 流终/非 text 帧 | HOLD 未决按确认阈裁决：已逐位匹配 ≥ confirmChars = 纯重放丢弃；未达 = 保守补放行 |

缺省：`gapMs=10_000`、`confirmChars=32`、`minEmitted=16`（`createReplayGuardPlugin` 可覆写；
`gapMs ≤0` = 插件整体直通关闭）。误判代价有界：发散路径只引入一个确认窗的延迟。**盲区（启发式固有）**：停顿后逐位相同的
合法重复（口令式复读、样板段 verbatim 重写）会被判纯重放吞掉——依赖确认窗收窄此面。

**与流空闲看门狗的交互**：看门狗测的是本守卫输出侧的帧间隔；扣留期零宽保活帧保证「上游
活着（重放进行中）」不被误杀——上游真死则无保活、看门狗照常超时止损。两者是互补而非独立。

## 2. 边界与非目标

- 检测边界：只覆盖「停顿后从头重放」形态（全部实证案例）；无停顿快速重放与「部分检查点
  重放」（重放起点在原流中段）结构性不可检测——依赖上游修复。
- 与 agent-loop 流空闲看门狗（docs/AGENT-LOOP-DRIVER.md §1.2.1）互补：重放守卫处理「停顿
  后有数据但重复」（保活帧防误杀），看门狗处理「停顿后永无数据」（真死流止损）。
- UI 打字机在 HOLD 窗口内暂停输出对应文本（帧被扣留）——发散时补发，视觉上为一个停顿。

## 3. 测试口径（`src/__test__/guard.test.ts`）

三态机全路径（直通/整文重发吞并/片段重放重同步/发散补放行/确认窗内分叉/流终两裁决/
非 text 帧两裁决/短文本直通）+ 流包装真实时延 + 插件装配全链（症状命名：回复正文重复拼接）。
