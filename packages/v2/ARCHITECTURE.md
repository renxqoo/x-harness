# 架构与边界

## 1. 目标

提供一个可组合、可隔离、可关闭、可诊断的通用插件宿主。任何应用的服务和流程均由插件定义。增加应用功能不能向 core 加入业务类型、固定业务扩展点或特殊判断。

core 的可用性意味着失败可观察、影响范围受控、资源有归属、停止状态真实；它不等于自动恢复应用业务。

## 2. 职责

| 内核机制 | 负责 | 外部插件负责 |
| --- | --- | --- |
| 契约 | 类型化标识、声明校验、Result、可选数据校验器 | 业务输入、输出、错误和数据格式 |
| 服务 | 提供者登记、绑定、门面、代次与受管调用 | 服务实现、状态、I/O 与算法 |
| 扩展点 | 调用链、通知事件、决策关口的执行机制 | 扩展点名称、流程和业务判断 |
| 装配 | 依赖图、暂存、发布、回滚和卸载保护 | 配置、外部依赖与初始化行为 |
| 作用域 | 可见性、拥有者、取消和关闭传播 | 应用实例的组织方式 |
| 任务与资源 | 在途登记、等待、取消、资源释放 | 队列业务、工作流、进程与执行宿主 |

core 不实现业务日志、持久存储、内容消息、上下文投影、检查点或可靠投递。`ctx.emit` 是内存通知，不是持久事件流。

## 3. 结构

全部实现位于 `/Users/wrr/work/x-harness/packages/v2`。工作区按以下边界组织：

```text
packages/v2/
  core/
  contracts/
  plugins/
  adapters/
  fixtures/
```

core 是纯内核包；工作区 contracts 保存领域契约，plugins 保存领域插件，adapters 保存外部接入，fixtures 保存应用组合验收。core 内部的 contracts 与 plugins 目录分别实现通用契约机制和装配机制，不包含外部领域实现。

内核源码结构：

```text
core/src/
  contracts/
  context/
  services/
  chains/
  guards/
  events/
  plugins/
  scopes/
  tasks/
  effects/
  diagnostics/
  index.ts
```

这些目录属于一个包，按职责组织，不分别发布。实现文件围绕一个动作，类型文件围绕一份契约。测试放在模块自己的 `__test__`。公开入口显式导出，不导出内部注册表和原始实现对象。

内部依赖方向：contracts 在底层；scopes、tasks、effects、diagnostics 管理生命周期；services、chains、guards、events 使用生命周期；plugins 装配这些机制；context 组合公共接口。底层模块不能反向导入 context 工厂或业务包。

core 的生产源码不导入其他 `@x-harness/*` 包，不读取文件、不访问网络、不读取 `process.env`、不注册进程信号、不调用 `process.exit`。计时与诊断通过宿主配置接入。运行时可以使用标准 Promise、AbortSignal 和本实例拥有的计时器。

## 4. 定义与身份

业务插件公开服务、chain、guard 和 event 的定义对象。消费者导入同一份定义，不按字符串临时生成副本。

定义工厂返回 Result，校验名称和描述形状。名称用于诊断和装配；对象身份用于关联类型与实例。一个根宿主中，两个不同定义不能占用同一名称。相同定义可以在不同作用域由不同实例提供。

异构注册表的类型擦除仅存在于内部存储和绑定处。不得把回调统一改成单参数函数，不得以 `as never` 将错配贯穿公开调用链。类型负例证明输入、输出、方法名和 token 不能互换。

## 5. Context 与拥有者

作用域是可见性边界，拥有者是资源与生命周期边界，两者不同。

同一装配作用域内的插件拥有独立的资源账本，但可以通过声明的依赖协作。每个注册、调用、任务、计时器和清理函数都有唯一拥有者。

插件取得受限 Context 门面；它不能得到宿主的 load、unload、dispose 或其他插件的私有账本。宿主取得 RootContext 控制接口。插件创建的子作用域归创建者拥有，创建者关闭时连同子作用域关闭。

```text
根装配作用域
  插件拥有者 A
  插件拥有者 B
  子装配作用域
    插件拥有者 C
```

作用域本身不含 agentId、roomId 或 tenantId。应用可以通过自己的服务表示这些身份。

创建子作用域不等于安装插件。独立插件图由持有 RootContext 的宿主通过 load 装配；禁止直接调用其他插件的 apply 绕过依赖和回滚。运行时需要创建实例的应用，由宿主提供外部受限实例管理服务：接受获准配置与参数，返回不透明实例身份，把子作用域绑定调用者拥有关系。该服务不把 RootContext 或跨作用域关闭权限交给插件。

实例管理服务检查 Invocation.phase，activation/cleanup 阶段拒绝同步创建，避免当前装配占用 mutation 队列时等待自己的后续装配。激活期间需要的子实例由宿主在批次提交后创建。运行期间创建和停止操作先返回受理身份，再由宿主协调工作，状态与结果通过外部服务读取。停止不能在被停止实例的调用栈中等待该实例自身关闭。

## 6. 可见性与依赖绑定

服务和扩展点只能从本作用域及祖先取得，不能搜索兄弟或子作用域。

同一作用域中同一服务或 chain 的提供者只能有一个。子作用域可以显式使用 `shadow: true` 提供同一契约的本地实现，默认拒绝遮蔽。父作用域不会因此改变其依赖。

本地遮蔽者卸载后，既有门面失效，本地新解析也不能悄悄回退到祖先实现；该本地绑定保留撤销状态，直到明确提供新的本地实例或关闭作用域。

插件在安装规划时绑定必需和可选依赖。可选依赖缺席时保持缺席，不因后续安装而动态出现。已经绑定的可选依赖参与卸载保护。改变绑定必须通过重新装配插件完成。

普通插件不能使用未声明的其他插件服务或扩展点。插件可以使用自己已经提供的契约。宿主可以显式解析所在作用域可见的公开契约。

## 7. 受管服务

公开服务是方法对象，每个方法采用单一参数对象或 void 输入，返回 `Promise<Result>`。同步纯函数可以作为模块内部 helper，不纳入受管服务接口。

提供者实现方法接收额外 Invocation；消费者的方法签名不暴露这个参数。宿主自动附加调用身份、来源、取消信号和剩余时间。

服务不强制 JSON，也不强制逐方法 schema。跨进程、持久化或外部输入的数据校验由相关插件补充。

`use` 返回门面，绑定消费者、提供者和提供者实例身份。方法提取后仍保持绑定。消费者关闭、提供者撤销或提供者实例变化后，新调用失败；旧门面不重定向到其他实例。

服务调用的资源属于 Invocation.resourceOwner。嵌套绑定调用保留此逻辑消费方，实际直接调用者仍由 origin 区分。清理权限来自资源创建执行者的固定依赖，资源未释放前不能卸载这些依赖。提供者长期资源登记在其 apply Context；为消费者创建的订阅等长期资源登记在 Invocation 的消费方资源账本。调用返回不会误关订阅。

嵌套调用通过 Invocation.bind(ctx) 显式建立父子关系，继承取消、截止时间和预算；普通 ctx.use 是拥有者级入口。绑定门面只有依赖调用能力，不增加依赖权限。清理门面独立于业务准入，固定依赖释放顺序并使用清理截止时间。

服务方法并不天然经过业务 guard 或 chain。业务服务必须公开自己的统一执行入口，把授权和受控执行组合在该入口中；不能另外暴露可绕过判断的原始执行函数。

## 8. 三类扩展点

### 通知事件

Event 是异步、有界的内存通知。载荷是经过快照校验的 JSON 数据，生产者身份由 core 附加。监听者不得修改共享载荷。

子作用域发出事件，只有本作用域及祖先的监听者可见。业务广播或跨作用域路由由插件实现。没有全局自动广播。

同一监听者按接受顺序处理事件；不同监听者可以并发。满队列明确返回 resource-limit，不默默丢弃。已入队但监听者随后撤销的工作被明确取消，不承诺可靠投递。

观察者异常进入诊断，不改变已完成的业务调用。诊断出口失败不能反向抛出或无限递归。

### 处理调用链

Chain 有一个终结处理器和多个有类型的中间件。中间件可以改输入、改输出、包装执行或短路。

每次 dispatch 捕获稳定执行计划。祖先处理器在外，本地处理器在内；同作用域按装配顺序及注册顺序排序。

允许顺序调用 next 多次，支持高级恢复插件。禁止并发 next、父处理器结束后的 next、取消后的 next，以及超过 continuation 预算的 next。每次 next 有独立调用身份，共享父调用截止时间和剩余预算。

调用 next 后未观察的失败、处理器返回时尚未结算的 next 都是契约错误。core 必须请求取消并追踪真实收敛，不能把失控 continuation 当成已经释放。

重试业务是否安全由领域契约和恢复插件判断。core 不自动重试，也不保证外部副作用仅执行一次。

### 决策关口

Guard 按确定顺序执行，全部明确允许才返回 allow。任一 deny 阻断；异常、取消、超时、非法返回和没有处理器都返回失败。

需要等待授权的插件可以等待自己的服务或任务；core 不内置 UI 请求或审批状态。Guard 只提供决策机制，不理解权限规则。

执行最终输入、环境身份及授权是否一致，由定义受控执行服务的插件契约保证。

## 9. 高可用与保证边界

core 保证管理自己登记的资源、调用和任务。超时或取消信号不等于底层工作已停止。提前返回失败后，实际工作仍留在账本中，直到真正结算。

关闭停止新增工作，取消在途工作，等待真实结束，再释放资源。清理失败不阻止其他资源释放。存在未结算任务或未确认释放的资源时，状态是 close-failed，不是 closed。

插件只请求关闭，不等待自身关闭。宿主的关闭接口与插件接口在类型上分离。

进程内插件属于可信代码。core 不能阻止它直接使用平台 I/O、保存外部裸函数、执行不让出事件循环的代码或制造未登记的 Promise。强制隔离和进程终止由外部执行宿主插件负责。事件校验和门面撤销不能被描述为沙箱。

批次原子发布是注册可见性保证，不是外部事务。跨进程可靠调用、持久恢复、跨流事务与恰好一次副作用均不属于 core 的承诺。

## 10. 领域事件、投影与恢复

`agent/message`、`tool/result` 等名称及载荷由外部领域契约插件定义，属于 Agent 运行事实。它们不能替换为仅有 emit 的通知，也不成为 core 预置事件类型。core 提供注册与调用机制，领域插件提供记录协议。

外部记录协议至少明确以下信息与规则：

| 协议部分 | 外部领域职责 |
| --- | --- |
| 事件身份 | 稳定 eventId、领域 type、schemaVersion、不可变 payload |
| 流内顺序 | streamId、持久 position、预期位置写入检查；时间戳不代替顺序 |
| 因果关系 | correlationId、causationId、操作身份；调用身份仅作为可选追踪信息 |
| 来源 | 根据受管调用来源及接入认证记录领域参与者，不从 user 角色猜测身份 |
| 投影 | 纯状态归约、已处理位置、版本匹配、重复记录幂等 |
| 检查点 | 业务快照、记录位置、格式标识、未决操作身份；禁止保存 JS 函数或执行栈 |
| 副作用 | 先记录意图、稳定操作身份、结果记录及未知结果处理协议 |

事实先通过外部记录服务持久提交，再更新投影或通知有新记录。记录成功后即使 emit 失败，消费者也能从持久位置补读。模型流式 delta 可以是瞬时进度，最终消息与工具结果是领域事实；领域必须定义二者关系，不能把每个 token 自动当作恢复边界。大内容使用外部存储引用，不突破内核内存通知预算。

检查点与位置必须一致：从检查点位置之后重放不可变事实，不能重放一次真实工具执行。进程中断后没有结果的外部操作可能已经发生，恢复插件依据操作身份查询、去重或明确报告未知；不可安全重试的操作不能因启动恢复自动重做。领域日志、投影和副作用的原子性由外部存储协议实现，core 的批次发布不提供这类事务。

插件可为自己的格式提供校验、升级和投影服务。core 不拥有统一业务 State、内置 reducer、checkpoint 命令或 run/session 字段。完善领域记录协议和验证恢复场景，不需要污染插件宿主边界。

## 11. 架构验收

新增业务必须通过定义公共契约、提供服务或注册处理器完成。core 的代码和测试夹具不能包含业务包导入或业务名称分支。

提示词、skill、压缩、纠错、权限、环境和房间在独立外部夹具中组合验证。它们可以有自己的数据结构与算法，不能重复绕开核心资源归属、调用身份和关闭协议。
