状态：已核销。与DESIGN.md同步维护。

## 1. 顺序

1. 盘点现有LLM源码、测试及上游协议，形成行为矩阵。确定三协议与首批模态，审查流消息的身份、终态、背压和生命周期。
2. 定稿设计与测试口径。保留当前工作区的751例及覆盖率门槛90/88/95/96，确认源码/构建入口测试装置接入路径。
3. 正式首切片：统一契约、请求/事件状态机、一个OpenAI Chat文本+工具流、单槽消费辅助函数、真实回环HTTP场景；四门及独立审查。切片用于验证流程与基础资源算法，不作为完整插件交付。
4. 扩展Responses与Anthropic，完成推理/签名、原生continuation、全部结束原因、usage累计及兼容端点的显式能力配置。每批保留前一批全量断言，禁止用静默丢字段凑兼容。
5. 完成图片/引用文档与搜索结果输入、结构化输出与引用、第三方provider公共检查器及类型/文档用例，接入构建与依赖边界。
6. 取消/超时/过载、畸形SSE、连接中断、早退、重入与关闭专项，源码与构建进程旅程、基准和隔离故障突变。独立审查具体问题逐项处置。
7. 全量四门、测试/覆盖率实际数字、资源与性能结果落档。使用文档只描述当前行为，审计矩阵核销每项能力，才标已核销。

## 3. 依赖与借件

复用core公开Result、插件定义、服务/chain与安全JSON读取；不得引用内核私有工作记录或更改服务生命周期来迁就裸迭代器。

传输使用标准fetch与ReadableStream。借用厂商SDK或现有pi层若不能保留必要原生事件、控制真实背压/字节预算、关闭和隐式重试，则不作为首批生产依赖。共享SSE工具只实现标准传输，不自行实现TLS、HTTP连接池或厂商完整业务运行时。JSON Schema校验采用Ajv并先执行DESIGN§4声明的安全子集校验，禁止临时手写通用验证器冒充完整校验；核查安装版本、包体、schema缓存及无引用/正则/分支的预算。编译异常返回Result，不输出schema原文或数据。

兼容协议是显式配置的能力与字段映射，不按厂商名字写散落的特殊判断。缺失某厂商扩展时返回可识别错误，不能承诺任意第三方端点完全等价。

## 4. 集成与共享工作区

开发使用已附着隔离worktree，先保存任务前路径与指纹。其他Agent在原目录的修改保留，不越界修门禁或覆盖共享文件；最终同步只处理本任务拥有的路径及必要的构建/测试入口，逐一比较基线。

已有packages/llm及其消费方用于审计，不整包复制，不在此任务删除仍被其他应用使用的包。新工作区只提供一套新契约，不留指向旧实现的转发别名；应用迁移与清理已无消费者的旧包是另一个有行为审计的任务。
