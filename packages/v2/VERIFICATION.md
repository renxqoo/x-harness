# 验收与测试计划

## 1. 验收原则

测试约束可观察行为、不变量和真实失败窗口，不按文件数量或覆盖率数字衡量设计质量。

覆盖率如实报告，用于发现未测试路径。不能降低门禁、扩大排除范围、添加 skip 或删除有效断言获得成功。计划用例数与已经运行的用例数分开报告。

本文件列出行为验收矩阵；实际通过的用例及命令记录见第 13 节。外部领域组合场景由对应领域插件验证，不能用内核单测替代其持久化、隔离和应用旅程。

## 10. 测试装置

时间与调度使用注入 Scheduler，不用长时间真实 sleep。用 deferred Promise 精确控制激活、调用、next、观察者和清理的交错时机。

提供者 spy 记录实际进入次数，尤其证明拒绝授权、预算不足、撤销和取消后没有执行。资源装置记录创建、登记、释放及剩余数量。

Result 断言检查 code、状态和可观察结果，不仅检查 ok。故障注入覆盖返回失败、同步 throw、异步 rejection、延迟结算和永不响应取消。

关键测试进行反向验证：故意破坏身份绑定、异常阻断、去重或清理顺序时，用例必须失败。反向验证采用临时补丁或测试装置，不能留下破坏源码的变更，也不使用销毁性 git 操作。

## 11. 性能与资源验证

不预先宣称具体性能提升。先建立独立基线，比较相同调用数量、作用域、插件、数据量和调度策略。

记录服务调用与 dispatch 吞吐、事件排队延迟、装配时间、关闭时间、峰值内存和多轮安装/卸载后的保留对象。稳定计划可以缓存，但登记变化必须使缓存失效。

常规业务调用不能扫描全部插件、全部作用域或完整历史。服务解析按作用域深度，依赖规划按图规模，调用按选中的处理器数，事件按匹配监听者数执行。

正常关闭的内部账本必须回零，heap 测量只是辅助。未收敛任务的引用保留是显式失败状态，不能在指标里隐藏。

## 12. 门禁与报告

每个代码里程碑运行模块测试及适用集成验证，并在 `/Users/wrr/work/x-harness/packages/v2` 独立工作区执行：

```sh
bun run lint
bun run typecheck
bun run build
bun run test
```

lint 必须实际使用类型感知配置。build 与 test 必须包含本工作区内核入口及用例，检查范围不依赖其他目录的实现。只运行本次修改对应 e2e，不运行 e2e 总入口。

报告实际运行的用例数、失败、类型负例数、覆盖率及适用限制。未运行就写未运行。文档审查、代码类型检查、实际运行和性能基准分别报告，不能相互替代。

文档校验、源码检查和运行验证分别记录；未经实际测量，不能宣称性能提升或第三方应用已经通过验证。

新增实现验收包括根宿主装配串行、父子装配与卸载竞态、清理执行者依赖权限、跨拥有者资源冲突，以及在线安装只影响后续调用。

## 13. 当前验证记录

运行用例统一位于 core/src/**/__test__/；具体模块与故障场景见 [测试说明](core/src/__test__/README.md)。测试使用真实公开入口，类型负例没有类型错误抑制，运行用例没有 skip 或被注释断言。

当前验证：175 个运行用例，13 个测试文件；18 个独立类型负例拒绝预期错误；公开入口正例、EXAMPLES 的 9 个代码块及 core/README 使用指南的 14 个代码块通过 strict 类型检查；使用指南快速开始也通过本地包 exports 实际执行。类型负例脚本同时拒绝导入扩展名导致的配置错误，避免因编译装置错误误判为接口约束有效。

本工作区的 typecheck、lint、build、test 均通过。build 将 55 个模块构建为浏览器目标 ESM；其产物不依赖 node/bun 平台 I/O。类型感知 lint 要求零警告、零错误，另检查 57 个生产源码文件的内部依赖边界、平台隔离、无类与无代码注释。

覆盖率用于遗漏诊断：语句 90.75%（1276/1406），分支 89.07%（864/970），函数 94.59%（210/222），行 96.43%（1000/1037）。统计排除测试夹具和只含类型声明的文件；没有数字覆盖率阈值替代行为断言。

三个定向故障注入均被回归测试检出：忽略同拥有者清理 pins、删除关闭完成时的时钟检查、自动 join 使用迟到成功。每次检查后恢复源码，完整验证使用恢复后的实现。

独立只读审查已完成多轮定向复验，其中一轮 53/53 通过。最后追加的派生排空期间新增分支定向复验 1/1 通过，确认 while 循环持续等待新增分支；完整四门也通过。审查发现的问题已转为回归用例，包括固定依赖权限、取消和真实收敛、清理代次、在线装配边界、派生 Continuation、校验器异常分类、GC 保留对象及子作用域级联关闭。

性能基准、真实 npm 包下载和跨进程应用旅程没有执行；它们不属于进程内内核的本次运行验证。根工程一次类型检查暴露 apps/hub-gateway 与 scripts 下既有类型错误；本次没有修改这些文件，也不将本工作区通过等同于根工程通过。

当前独立对抗审查仍确认 13 组未解决问题（4 项 P1、8 项 P2、1 项 P3），涉及关闭收敛、Signal 初始化、装配发布与回滚、期限和能力引用。详见 [对抗审查记录](reviews/core-adversarial-2026-10-15.md)。现有门禁通过不能作为这些问题已经修复或内核已完成生产验收的证明。
