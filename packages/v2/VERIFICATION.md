# 验收与验证记录

## 适用范围

本记录适用于 packages/v2 独立工作区，包括通用内核、standard/application/loader/create、公开类型、文档示例及应用组合夹具。它不表示仓库其他工作区的门禁已经运行。

测试以公开入口检查可观察行为，并直接验证所属模块的Result读取及等待图算法。不得降低覆盖率阈值、增加 skip、删除有效断言或以编译导入失败冒充类型约束。测试位置及场景见 [测试说明](core/src/__test__/README.md)。

## 真实应用与轮换压力

普通服务端夹具使用真实 bun:sqlite 与 Bun.serve，在回环地址发送 HTTP 请求，检查用户查询、404、依赖调用、级联卸载与重新安装。连续两轮后连接、服务器、范围、租约与工作归零；它不依赖任何 AI 包。领域组合夹具也通过同一公开入口运行，业务类型位于 core 外部。

三个固定随机种子各执行 128 步混合操作，逐步核对安装状态、调用结果、事件投递、取消、受控安装失败、临时范围关闭、释放次数与撤销门面。

可重现的一万轮检查：

```sh
bun scripts/check-rotation.ts
BUN_JSC_useJIT=false bun scripts/check-rotation.ts --collect
```

两种运行均通过。每轮执行安装、资源取得、服务调用、卸载、旧门面拒绝及账本核对；共创建并释放 10000 个资源。默认 JIT 运行结束时所有账本为零；精确引用运行中 10000 个动态 token 全部回收，宿主在检查前保持活跃。

默认 JIT 测量的第 8000—10000 轮 heapUsed 为 3976259、3977867、3977868 字节。这是单机短时压力观测，不能据此宣称长期内存曲线或延迟 SLO 达标。

## GC 测量与反向验证

撤销定义的独立 GC 夹具保持根和子范围存活，要求全部撤销 token 消失。默认 JIT 下偶发的保留在保存基线和当前实现均可复现；读取 WeakRef 之前的堆快照显示 DefinitionData 由 GC roots 直接保留，而非活跃注册表路径。相同输入关闭 JIT 后连续 200/200 次通过。

因此，仅该精确引用测量子进程关闭 JIT，断言、GC 轮数和宿主存活条件保持不变。普通功能测试继续使用默认 JIT。强 tombstone Set 的故障注入仍被该 GC 断言拒绝，不以账本为零替代真实引用回收。

取消回收夹具保持Owner和Invocation存活，同站点一次预热、8个正式取消样本全部断言、末尾再调用一次。完全不含内核或AbortController的[Promise复现](reviews/benchmarks/promise-home-object.ts)在Bun1.4.3关闭JIT时，方法形式100次保留首/末样本，arrow仅末样本；[原始记录](reviews/benchmarks/promise-home-object-results.json)限定了测量边界，不能声称全部调用零保留。正式样本未见额外保留；成功工作业务监听闭包与已关闭Kernel亦可回收。两个永久负控制分别故意持有外部source和构造携带原reason的AbortSignal.any，均被同一回收断言拒绝。

本次隔离源码突变删除取消源去重、删除完成回调解绑，均由预期行为断言检出；此前惰性依赖的两项突变仍保留结果记录。

声明类型的十项隔离突变覆盖optional必需化、额外字段放行、缺席表授权、泛型结构越权、任选联合分支、重叠方法协议联合、隐藏联合额外键、服务输入扩大，以及资源/实现泛型包装短路。每个目标用例先证明正常代码产生API使用诊断，再证明突变后错误用法会编译成功；模块解析失败不算检出。合法能力超集、Pick最小接口、同协议动态名称及正确反向任务/资源/实现赋值仍通过正例。仅类型重组的核心浏览器bundle在保留标识符、压缩语法与空白的相同配置下逐字节一致，结果见[运行时代码核对](reviews/benchmarks/authoring-runtime-equivalence.json)，不把类型改进计作吞吐收益。

独立源码副本上的六项故障注入均由断言检出：

| 人为破坏                       | 检出的行为                   |
| ------------------------------ | ---------------------------- |
| 取消暂存子范围访问屏障         | 提交前取得未发布能力         |
| 服务门面每次重新解析当前提供者 | 保存的旧门面在重新安装后复活 |
| 关闭只等待 outcome             | 实际工作结束前释放资源       |
| 不建立清理依赖 pin             | 提供者被过早卸载             |
| 处理器捕获不按范围过滤         | 兄弟监听者收到事件           |
| tombstone 使用强 Set           | 活跃范围保留全部撤销 token   |

突变只发生在隔离临时副本，不修改交付源码。完整门禁使用正常实现运行。

API 职责另有四项隔离副本故障注入：取消处理器种类检查、跳过声明激活、绕过事件发送权限、接受 Result 的未知失败字段，均被 public-api 回归断言检出。

## 审查与限制

多轮独立只读审查发现的问题已转成回归，包括门面状态快照、恶意名称强制转换、批量提供的半提交、临时租约失败缓存、清理资源身份、暂存子范围、迟到微任务和取消后的资源清理父项。混合操作检查另外覆盖相同 token 重新安装后的暂存依赖。空能力批次也在不可信 options 描述器读取后重新检查准入，宿主已停止时不会报告提供成功。

尚未执行 60 分钟持续运行、同条件多轮延迟分位基准、发布包下载安装或硬件断电恢复。这里不宣称性能最优、不中断替换或分布式高可用认证。进程内无法强制中断的执行由外部 Worker/进程监督处理，持久化与业务恢复属于外部插件。

## 原生作者与在途替换对照

六个公开入口夹具运行服务、异步资源、生命周期任务、事件、提供者替换及在途资源排空。双方完整对照另以 `bun scripts/compare-journeys.ts /absolute/path/to/cordis` 运行，普通门禁不依赖该外部目录。[实现与边界说明](scripts/comparison/README.md)及[原始结果](reviews/benchmarks/author-journeys.json)保留编译器、类型依赖、实际生成声明、源码和测量工具指纹，运行结束再次检查。

本系统与Cordis作者代码由同一TypeScript7.0.2以strict及noUncheckedIndexedAccess检查并分别执行；Cordis真实声明先由自己的TypeScript5.9.3及项目配置生成。四个错误作者副本在服务输入或事件payload的修改位置产生语义诊断，导入失败或进程超时不算检出。任务两方都能等待实际Promise，Cordis示例通过公开disposer手动abort及join。

在途调用门保持关闭并刷新128个微任务后，受管调用仍保有资源且替换未完成；放行并真正结束后才完成替换。删除实际工作排空的隔离源码副本被相同期望拒绝，表现为提前关闭、提前完成替换且旧函数继续使用已关闭资源。最初过早释放gate的实验漏检该突变，独立审查发现后已补强；这一有界观察不能推广成所有调度交错的证明。旧入口的具体差异及非等价语义见[对照记录](reviews/kernel-comparison-log.md#原生作者旅程与替换语义)。该作者对照不修改生产运行时，不产生性能收益结论。

## 诊断专项验证

25 个公开入口用例覆盖固定/可选依赖、跨范围同名实例、宿主资源 pins、实际未结束工作、并行手动清理精准定位、子范围过滤、有界采样、70000 字符合法方法名、历史快照冻结、恶意 token 描述器和 sink 抛错/重入。错误回执与对应诊断共享冻结详情；范围关闭与卸载迟到成功不重复生成超时记录。

独立只读审查发现手动关闭漏报清理工作、长方法名撑破详情限制两项问题，均已修正并通过原始复现与新增回归。两项精确 GC 测量保持快照、错误及诊断存活，验证活跃宿主不保留退休 token、关闭宿主可释放；使用独立关闭 JIT 的子进程，常规功能测试仍使用默认 JIT。复核额外保持手动 disposer，确认临时清理工作关联不会留住已排空内核。

六项诊断故障注入只在临时源码副本运行：直接输出 token、取消详情冻结、取消列表采样、混入兄弟范围工作、取消清理工作关联、取消方法标签截断。六项均被行为断言检出，正常源码未应用突变。未降低覆盖率门槛，未新增 skip 或删除有效断言。已有 execution-budget 回归中的空任务断言随公开契约改为检查空 work，实际验证范围覆盖调用和任务。

## 外围平台验收

standard检查日志元数据总预算、配置读写权限与队列提交、周期任务不重叠、实际工作及子工作结束后再续调、关闭后定时器归零。派生Context和依赖门面的撤销回归保持公开句柄存活，检查卸载后token可以回收；活跃宿主上已丢弃的定时工具也不保留调度器。

application检查完整期望集合、缺失依赖待定、提供者及可选依赖变化后的传递重装、失效旧门面、有界队列及未排空资源阻止替换。loader分别通过源码和构建入口运行真实HTTP服务热更新、失败更新保留服务、文件监听恢复及关闭排空。源码与构建副本在同一进程共享64次导入预算；多入口部分准备失败不重复导入，清理迟到收敛可以复用准备结果。脚手架真实子进程完成生成、类型检查、测试、构建、源码启动和构建产物启动，路径含空格；生成失败保留未完成目录，竞争者文件和目录不被自动删除。

四项额外隔离故障注入分别放开import.meta逃逸、拆分进程导入预算、保留撤销依赖引用、保留已删除监听目录，全部由行为断言检出。未用模块解析失败冒充检测成功。独立复核处置及验收边界见[平台验收记录](reviews/kernel-platform.md)。

## 依赖门面性能与编写约束

公开回归覆盖未用依赖不创建逐调用上下文、过期首次读取的完整方法形状、不同Owner可选依赖隔离、已取得与未取得依赖的不同错误码、cleanup首次读取旧依赖及超时后迟到访问。动态Record服务表有编译正例，错误方法类型和固定声明额外服务有负例，运行时仍检查完整性并原子登记。

同一测量器执行两组反向顺序的改前/改后测量，每组每场景每实现7个独立子进程，完整保存异常慢样本。未读取依赖的两类调用成本下降；四层依赖的变化不足以证明收益，普通对象派发仍明显快于受管调用。精确数据、可在隔离副本重建基线的补丁及限制见[迭代记录](reviews/kernel-comparison-log.md)。两项隔离突变分别提前物化依赖、让过期首次读取返回空对象，均由行为断言检出。

## Result读取与等待环验证

Result规范化直接读取两个自有数据属性，避免通用对象副本及二次键枚举。成功值与业务错误保留身份，合法字段顺序、不可枚举及null原型继续接受；访问器、畸形字段、非普通原型及Proxy异常仍拒绝。畸形字段集合可在描述符读取前被拒绝，不保证无效Proxy元操作的次数；合法两字段结果的读取顺序保持。新增33个结构用例、2个公开服务/任务回归、4个等待图用例和1个三任务传递环回归，共40个测试。

[差分脚本](reviews/benchmarks/compare-result-boundary.ts)对真实改前后实现运行1880组输入，包括Proxy变异、撤销和重入，结果一致；脚本本身亦通过strict及noUncheckedIndexedAccess检查。[六项突变](reviews/benchmarks/result-boundary-mutations.json)分别引入访问器执行、额外字段放行、非普通原型放行、truthy判别、CoreFault绕过及等待环放行，全部被预期行为断言检出，未用超时或导入失败过关。[脚本](reviews/benchmarks/result-boundary-mutations.py)可从源码重跑，正常工作树不应用突变。独立审查另完成定向测试和1880组差分，无确认安全或语义阻塞。[作者旅程与实际排空负控制复测](reviews/benchmarks/result-author-journeys.json)亦通过。

同一测量器的两组反向顺序测量，普通调用合并中位数2.019→1.932µs，下降4.34%；未使用16依赖场景1.991→1.932µs，下降2.95%。四层调用11.555→11.424µs，变化1.13%，不认定收益。等待图叶节点候选方向不一致，已从生产代码撤回，保留样本及回归。全部样本、可重建基线的补丁与限制见[记录](reviews/kernel-comparison-log.md#固定result读取与被撤回的等待图候选)，不宣称尾延迟、吞吐饱和、内存或Cordis性能领先。

## 按槽位创建依赖门面

依赖表固定全部可枚举名称，多服务槽位首次读取才生成并缓存对应门面；单服务直接创建唯一门面。全部槽位共享可撤销source，结束时清空，getter不直接捕获token或Kernel。已取得服务在撤销后返回service-unavailable，未取得服务返回cancelled。三个行为用例覆盖完整冻结形状、缺席optional、名称constructor、提取方法、失败重试和迟到读取；相同用例在保存的改前源码亦通过。

四个独立GC子进程分别保存setup依赖表、Invocation依赖表、部分服务门面和关闭宿主后的门面。同站点预热一次、8个正式样本逐个断言、末尾调用一次，隔离已复现的VM首/最近帧保留；不把预热及末尾样本计作零保留。每种场景检查136个正式token，合计544个，另检查8个关闭Kernel标记，均可回收。前三种场景保持宿主活跃，不能用关闭整个宿主掩盖退休token泄漏。
